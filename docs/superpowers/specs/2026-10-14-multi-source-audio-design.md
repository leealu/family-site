# 多音源搜索与网页播放设计

## 目标

让家长能够在“编辑网站”后台配置一个或多个音乐/故事音源，按歌名、艺术家、绘本或故事专辑名搜索，并把选中的内容加入兴趣卡片。访客在兴趣卡片中点击播放后，直接由网站内的播放器播放可用音频。音源不可用时显示来源和明确的失败提示，保留手动换源入口。

“尽量多源可播”是目标，不承诺所有曲目都可用。版权、地区、账户权限、接口变化和网络条件均由音源服务决定。

## 已确认的方向

- 播放来源可配置，不固定为网易云。
- 搜索和播放服务由站点后端访问，接口密钥不下发到访客浏览器。
- 音乐和故事内容都可以纳入搜索；具体能搜索到哪些类别，取决于已配置的音源。
- 网站将曲目元数据和来源标识保存到兴趣内容；播放时再向来源服务解析当前播放地址，避免长期保存可能过期的临时 URL。
- 访客能播放家长已经添加到兴趣卡片的曲目；搜索、音源配置和曲目管理只对家长开放。
- 保留现有上传音频和网易云外链，作为兼容和备用内容。
- 不执行用户上传的任意 JavaScript 音源脚本，不实现绕过登录、会员、访问限制或版权校验的逻辑。

## 与 LX Music 的关系

LX Music 桌面版的开放 API 主要用于控制本机正在运行的播放器及读取播放状态；自定义源则供 LX 播放器调用。它们本身不是适合远程网站访客使用的共享搜索与播放 API。网站不要求访客安装或运行 LX Music。

如果用户提供的服务具有可由服务器访问的搜索和播放地址，可以通过服务适配器接入；仅提供 LX 桌面开放 API 或 `.js` 自定义源文件时，不能直接作为站点音源。

## 技术方案

### 音源适配器

在 `server.py` 中增加服务端音源适配器层。每个适配器负责：

1. 使用关键词搜索一个已配置音源。
2. 将供应方结果转换成站点统一的数据结构。
3. 使用曲目 ID 和供应方信息获取当前播放 URL。
4. 将超时、无结果、无可用播放地址、上游拒绝访问等错误转换为简短且不泄露密钥的站点错误。

第一版支持 **Meting API 兼容协议**，由家长填写 API 服务地址、平台代码和可选服务密钥；站点适配器调用其搜索、歌单/专辑和播放 URL 解析接口。具体平台能否搜索故事/播客由该 API 提供方决定。后续可增加其他协议适配器，但第一版不执行 LX Music `.js` 音源脚本。

选择这个协议是因为它定义了多平台 HTTP/JSON 接口；这不意味着任意 Meting API 服务均稳定、获得曲目授权或能播放所有平台。接入前要确认服务端可达性、接口实际返回值及来源限制。GitHub 仓库开源不等于曲目已获播放授权。

协议映射按 Meting 常见调用方式实现：用 `server`、`type=search`、`id=<关键词>` 搜索；根据搜索结果中的曲目 URL ID 调用 `type=url` 解析播放地址；需要认证签名时由服务端根据配置计算，不在浏览器生成。适配器只读取有限大小的 JSON 响应和解析播放地址的响应头，不下载音频字节。若某个 API 变体改变参数或响应字段，需新增适配器或修正配置，而不是开放任意 URL 代理。

统一的站点曲目对象：

```json
{
  "providerId": "source-key",
  "providerName": "音源名称",
  "itemId": "provider-item-id",
  "kind": "song",
  "title": "曲目或故事标题",
  "creator": "歌手、讲述者或作者",
  "collection": "专辑、绘本或故事集",
  "coverUrl": "https://...",
  "durationSeconds": 123
}
```

播放 URL 不写入该对象；服务端根据 `providerId` 和 `itemId` 重新解析。数据只接受已配置音源返回的 HTTPS URL 或家长自行上传的本地媒体引用。

### 后台音源配置

在“编辑网站”新增“音源设置”管理页。第一版每个音源记录包含显示名称、协议（固定为 Meting API 兼容）、服务端 API 基址、平台代码（如服务支持的网易、QQ、酷狗、百度或酷我）、可选服务密钥、启用状态和优先级。保存前执行连通性/协议测试并显示结果。输入的地址必须是明确配置的服务地址；访客请求不接受 URL、平台代码或密钥覆盖已保存配置。

配置和密钥保存在 SQLite 的私有设置项中：

- `/api/state`、公开页面内容和访客接口不返回密钥。
- 只有家长会话可以查看配置状态、编辑配置或发起搜索。
- 页面只显示已配置/未配置状态，不回显完整密钥；更新密钥时由家长重新输入。
- API 密钥只供服务进程读取，依赖服务器数据目录的文件权限保护；不会通过浏览器、日志或备份导出。
- 配置不进入公开备份文件；恢复备份不覆盖当前服务器的音源密钥。
- 上游请求设置连接/读取超时、响应大小限制和允许的协议；不接受访客传入任意 URL，避免形成开放代理或 SSRF 入口。

### 搜索与添加

家长在兴趣卡片编辑器中输入关键词并选择“歌曲”或“故事/专辑”，后端并行搜索所有启用的音源。结果展示标题、创作者、专辑/故事集、封面和音源名称。第一版保留各音源的独立结果，不做可能误合并不同版本的自动去重。若一个服务端点并不兼容 Meting API 协议，不能只填地址直接使用，需先增加对应服务端适配器。

家长选择结果后，兴趣卡片保存统一曲目对象。创建、编辑和删除曲目沿用现有“编辑网站”保存流程。只搜索不添加时不写入家庭内容。

### 播放与故障处理

- 公开兴趣卡片显示曲目信息、音源标识和原生 HTML audio 播放控件。
- 点击播放时，站点后端只为已被公开兴趣卡片引用的已保存曲目解析播放 URL；访客不能传任意歌曲 ID 或上游地址来调用代理。
- 成功解析后，浏览器直接从音源 URL 播放，不经本站中转音频字节，以避免占用家庭服务器带宽。
- 临时 URL 在播放时获取，不持久化；如源站要求浏览器 Cookie、特定 Referer、拒绝跨域媒体播放或资源失效，则提示播放不可用，并显示该曲目的其他已添加音源或外链（若存在）。
- 不自动切换到名称相似但可能不是同一录音的歌曲；由用户选择备用结果，避免故事内容错误。
- 保留浏览器对用户手势、静音和自动播放的限制；不在页面加载时自动播放。

### API 草案

- `GET /api/music/config`：家长专用；读取音源列表的非敏感字段和配置状态。
- `PUT /api/music/config`：家长专用；创建或更新音源设置，密钥写入私有配置。
- `POST /api/music/test`：家长专用；用指定配置做连接及协议测试。
- `GET /api/music/search?q=...&kind=...`：家长专用；查询已启用来源并返回统一结果对象。
- `GET /api/music/play/<saved-item-key>`：访客可用；只对当前公开兴趣内容中引用的条目解析临时播放地址。

搜索结果添加到兴趣内容时生成随机的 `savedItemKey`；播放接口先验证该 key 仍被公开内容引用，再按私有音源设置和记录的曲目 ID 调用适配器。

所有接口限制关键词长度、结果条数、响应大小及调用超时；配置变更和播放解析不记录密钥或完整上游认证参数。

## 数据兼容与备份

- 兴趣媒体中新增 `provider-track` 类型，保存统一曲目对象、稳定的本站 `savedItemKey` 及供应方曲目 ID；播放接口按 `savedItemKey` 查找当前公开兴趣内容，不接受任意供应方曲目 ID。旧 `netease` 项和上传图片、视频、音频继续工作。
- 旧配置、旧数据库、旧备份缺少音源配置时表现为“未配置”，不影响网站启动。
- 曲目元数据随现有完整备份保存；API 密钥与私有音源配置不纳入备份。
- 删除兴趣卡片或曲目只移除本站元数据，不删除上游服务的音频。

## 小程序兼容

当前网站 API 使用统一曲目对象和本站 API 路径；供应方协议只在服务端适配器内。未来小程序可复用搜索结果、曲目元数据和服务端播放地址解析，再由小程序播放器实现其客户端播放能力。当前阶段不加入微信登录、打卡或学习工作台功能。

## 不在第一版范围内

- 保证任意平台、任意歌曲和故事都可播放。
- 自动抓取网页并绕过验证码、登录、VIP/会员限制、Referer 或 DRM。
- 解析、安装或运行 LX Music 的任意自定义源脚本。
- 本站代理、缓存、录制或重新分发上游音频。
- 自动同步上游歌单变化或自动下载音频文件。
- 游客自由搜索整个上游曲库。

## 错误处理与用户提示

- 无可用音源：提示家长先配置 API，上传音频仍可使用。
- 上游搜索超时或失败：显示对应音源失败信息，其他来源结果照常显示。
- 无匹配结果：提示尝试歌手、讲述者或更短关键词。
- 解析或播放失败：提示“这个来源暂时无法播放”，显示来源及可选备用来源，不显示密钥、Cookie 或内部服务报错详情。
- 配置测试失败：指出 HTTP/JSON 协议、授权、连通性或 HTTPS 验证阶段，但对外隐藏敏感响应内容。

## 实现文件预期

- `outputs/site/server.py`：音源配置存储、适配器、家长权限、搜索与播放解析接口。
- `outputs/site/app.js`：音源设置、兴趣编辑器搜索/添加、访客播放器和失败提示。
- `outputs/site/style.css`、`outputs/site/admin.css`：搜索结果、播放器和移动端布局。
- `outputs/site/index.html`：静态资源版本号。
- `outputs/site/README.md`：配置、网络可达性、接口要求与权限边界。
- `outputs/family-site/` 和 `outputs/family-site.zip`：同步部署包，不覆盖或删除服务器数据目录。

## 需要用户审阅确认的实施选择

第一版准备采用“服务端适配器 + 家长配置 Meting API 兼容服务 + 家长搜索并添加 + 访客播放已添加曲目”的边界。API 服务必须能从家庭服务器访问，并提供搜索及播放地址解析能力。LX Music 桌面开放 API 和 LX `.js` 自定义源不满足这个服务协议；若用户有一个具体的 LX 音源服务端地址或其他接口样例，可以在实施前据此调整适配器范围。
