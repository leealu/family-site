# 成长日记照片与视频实现计划

> **执行说明：** 本计划等待用户审阅并选择执行方式后再实施。当前工作区不是 Git 仓库，因此不包含提交步骤。按会话约束，不新增或运行测试；实现后仅做代码审阅和部署包文件核对。

**目标：** 为每条成长记录添加多个图片/视频附件，对访客公开展示，同时仅允许家长管理，并保持年龄/日期翻页及完整备份可用。

**架构：** 在 SQLite `records` 表中增加 JSON 文本 `media` 列，媒体文件继续存于 `data/media/`。公开读取记录，写操作保持家长会话保护；家长编辑附件或确认删除记录时才清理不再被其他内容引用的文件。

**技术栈：** Python 标准库 HTTP/SQLite、原生 JavaScript、HTML/CSS、Docker Compose。

**设计说明：** [2026-10-13-diary-media-design.md](../specs/2026-10-13-diary-media-design.md)

## 全局约束

- 游客可看日期、年龄、标题、正文、图片和视频；只有家长能新增、修改、删除。
- 每条日记可添加多个图片/视频，单文件最大 200 MiB，沿用现有允许类型。
- 保留日期/年龄排序、年龄书签和翻页交互。
- 只有家长明确移除附件并保存，或确认删除整条记录，服务端才清理附件；若仍被其他页面内容引用则保留。
- 附件纳入现有完整备份和恢复；旧数据库/旧备份无 `media` 字段时按空列表兼容。
- 不添加或运行测试；完成后做代码级审阅并核对部署包包含更新文件。

## 重点审阅条件

- 未登录 API 状态返回记录与附件，但绝不允许游客调用写接口。
- 旧数据库迁移后所有旧记录可见，附件列表为空。
- 旧版本备份可恢复；新备份中的附件文件与记录引用一致。
- 删除/移除附件不会误删仍被兴趣卡片、头像或其他记录引用的媒体。
- 非图片/视频、不支持的扩展名、无效媒体 URL、超限文件和恶意压缩包路径被拒绝。
- 取消编辑、上传失败、刷新或删除确认取消，不会偷偷删除已保存附件。
